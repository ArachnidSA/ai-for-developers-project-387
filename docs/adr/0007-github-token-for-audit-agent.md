# Агент аудита авторизуется через `GITHUB_TOKEN`, а не через GitHub App

Аудит по расписанию (`.github/workflows/audit.yml`, события `schedule` + `workflow_dispatch`)
запускает агент OpenCode, который читает отчёт Lighthouse против публичного адреса приложения и
по новой находке открывает issue. Прочие агентские воркфлоу (`opencode.yml`,
`opencode-triage.yml`) ходят через GitHub App: `id-token: write` воркфлоу обменивает на токен
установки приложения. Для аудита выбран другой путь — `use_github_token: true` с репозиторным
`GITHUB_TOKEN`, правами `contents: read` и `issues: write` и **без** `id-token`.

Причина — минимальные права под фактические операции. Агент только читает отчёт, ищет
существующие issue и создаёт один новый; ветки и PR ему не нужны. У действия **нет входа
«создать issue»**: issue открывает сам агент инструментами (через `gh`), поэтому ему нужен
`shell`. Токен, у которого нет права писать `contents` и открывать PR, физически не может
протащить коммит — это и закрывает требование «отчёты не попадают в коммиты». Заодно
порождённые `GITHUB_TOKEN` события не запускают новые прогоны (кроме `workflow_dispatch` и
`pull_request` с подтверждением), поэтому созданный issue не уходит в петлю с
`opencode-triage`.

По той же причине `agent: plan` (как в `opencode-triage`/`opencode-review`) здесь не подходит:
у `plan` команды `shell` остаются «permission-controlled», а подтверждать их в headless-раннере
некому. Аудит запускает отдельного primary-агента `audit`, у которого `edit` запрещён везде,
кроме файла `audit-summary.md`, а `shell` разрешён только на `gh issue *` и `gh search *`.

## Рассмотренные варианты

- **GitHub App / OIDC (`id-token: write`)** — единообразно с остальными воркфлоу, но выдаёт
  права установки приложения (шире нужных: запись в репозиторий и PR) и требует
  установленного приложения. Отвергнуто.
- **`GITHUB_TOKEN` с `contents: write`+`pull-requests: write`** — так документация советует для
  расписания, но это нужно лишь тем задачам, что создают ветки/PR. У нас таких нет. Отвергнуто.

## Следствия

- Автор создаваемых issue — `github-actions[bot]` (в App-режиме был бы `opencode-agent[bot]`).
  Дедупликация на это не опирается: отпечаток находки задаётся меткой `audit` и заголовком.
- Ограничение агента операциями `gh issue`/`gh search` — часть решения: оно делает
  «не коммитим отчёты» свойством конфигурации, а не обещанием в промпте.
