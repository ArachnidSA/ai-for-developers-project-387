# Критерии ревью (REVIEW.md)

`opencode-review.yml` прогоняет дифф каждого PR против этих критериев и оставляет отчёт
комментарием. Каждую находку помечай уровнем:

- **Blocker** — мержить нельзя: баг, регрессия, нарушение контракта, секрет в коде.
- **Should-fix** — стоит поправить до мержа: тесты, обработка ошибок, конвенции.
- **Nit** — необязательно: стиль, формулировки.

## Что проверяем

1. **Корректность и регрессии.** Дифф делает заявленное и не ломает соседнее поведение; покрыты
   крайние случаи (пустые поля, конфликт слота `409`, часовые пояса).
2. **Тесты.** Есть тесты на изменение; проверяют внешнее поведение, а не реализацию; существующие
   проверки не ослаблены и не удалены.
3. **Контракт.** Источник истины — `contract/main.tsp`. `contract/openapi.json` и
   `frontend/src/api/generated/**` руками не правятся; при правке контракта они перегенерированы
   (`mise run gen`) и закоммичены. HTTP-контракт меняется только по делу.
4. **Конвенции репозитория.** Conventional Commits; линтер фронта — oxlint (не ESLint);
   `ruff` с `line-length = 100` и правилами `E,F,I,B,UP,SIM`; mypy — только `app tests`; доменные
   термины по `GLOSSARY.md`; решения не противоречат `docs/adr/`.
5. **Безопасность и конфиги.** Нет секретов в коде и в бандле (`VITE_*` публичны); `.env` не в
   репозитории; проверки не отключены без причины.
6. **Область (scope).** Нет изменений сверх issue/спеки; дифф сфокусирован.
7. **Читаемость.** Имена раскрывают смысл; нет дублирования и спекулятивной обобщённости;
   комментарии объясняют «почему», а не «что».

## Формат отчёта

```
## Blocker
- <файл:строка> — <проблема>; критерий №N.

## Should-fix
- …

## Nit
- …

## Итог
Blocker: N, Should-fix: N, Nit: N
```

Пустые разделы не выводим. Если находок нет — пишем одну строку «Замечаний нет».
